# TargetMatch

Перевірка, чи координати цілей потрапляють у заданий радіус навколо точок інтересу. MGRS і WGS84 розпізнаються автоматично, без ручного вибору формату.

Немає збірки, сервера, фреймворків. Кілька файлів + одна готова бібліотека.

## Як запустити

Відкрийте `index.html` у браузері. Інтернет не потрібен: конвертер лежить у `vendor/mgrs.min.js`.

## Як запустити тести

Потрібен лише Node.js (18+, вбудований тест-ранер, без встановлення залежностей):

```
node --test
```

## З чого складається

| Файл | Роль |
| --- | --- |
| `index.html` | Два поля вводу (точки інтересу, цілі), перемикач радіуса, таблиці результатів |
| `styles.css` | Зовнішній вигляд |
| `core.js` | Чиста логіка без DOM: парсинг, авто-визначення формату, відстані, пошук влучань — саме це покрито тестами |
| `app.js` | DOM-рендер: малює таблиці, кнопки копіювання, іконки — використовує `core.js` |
| `vendor/mgrs.min.js` | Готова математика MGRS/UTM |
| `tests/core.test.js` | Тести для `core.js` (успішні сценарії, невалідні/порожні рядки, дублікати, межа радіуса тощо) |

## Як це працює

1. **Точки інтересу** — до 10 координат (MGRS або WGS84, по одній на рядок), і радіус перевірки: 0.5 км або 1 км.
2. **Цілі** — довільний список координат (теж MGRS/WGS84, авто-визначення для кожного рядка).
3. Кнопка «Перевірити цілі» рахує відстань (формула гаверсину) від кожної цілі до кожної точки інтересу.
4. У таблицю результатів потрапляють **лише** цілі, що опинились у радіусі хоч однієї точки — сама їхня присутність у списку і є фактом влучання.

Рядки, які не вдалося розпізнати як координати, не зникають мовчки — про них повідомляє текст під відповідним полем.

## Куди дивитись новачку

1. `core.js` → `convertOne()` — авто-визначення MGRS/WGS84 для одного рядка.
2. `core.js` → `haversineKm()` — відстань між двома точками по земній кулі.
3. `core.js` → `findHits()` — зв'язує точки інтересу, цілі й радіус у фінальний список влучань.
4. `app.js` → `runCheck()` — викликає `core.js` і малює результат у DOM.

## Що навмисно не зроблено

Один спільний радіус для всіх точок інтересу (а не свій на кожну), координати лише колонкою (без міток типу «Харків - ...»), без збереження точок інтересу між сесіями. Можна додати пізніше, коли знадобиться.
