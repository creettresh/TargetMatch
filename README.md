# TargetMatch

Перевірка, чи координати цілей потрапляють у заданий радіус навколо точок інтересу. MGRS і WGS84 розпізнаються автоматично, без ручного вибору формату.

Немає збірки, сервера, фреймворків. Кілька файлів + одна готова бібліотека.

## Як запустити

Відкрийте `index.html` у браузері. Інтернет не потрібен: конвертер лежить у `vendor/mgrs.min.js`.

## Як запустити тести

Потрібен лише Node.js (18+, вбудований тест-ранер, без встановлення залежностей):

```
node --test
```

## З чого складається

| Файл | Роль |
| --- | --- |
| `index.html` | Два поля вводу (точки інтересу, цілі), перемикач радіуса, таблиці результатів |
| `styles.css` | Зовнішній вигляд |
| `core.js` | Чиста логіка без DOM: парсинг, авто-визначення формату, відстані, пошук влучань — саме це покрито тестами |
| `app.js` | DOM-рендер: малює таблиці, кнопки копіювання, іконки — використовує `core.js` |
| `vendor/mgrs.min.js` | Готова математика MGRS/UTM |
| `tests/core.test.js` | Тести для `core.js` (успішні сценарії, невалідні/порожні рядки, дублікати, межа радіуса тощо) |

## Як це працює

1. **Точки інтересу** — до 10 координат (MGRS або WGS84, по одній на рядок), і радіус перевірки: 0.2 / 0.5 / 1 / 2 км. Перемикання радіуса після першої перевірки одразу перераховує результат.
2. **Цілі** — довільний текст: координати (MGRS/WGS84, авто-визначення), можна з підписами й будь-якими роздільниками — «Харків - (33TWN0838825205), Одеса - 46.482526, 30.723309», вставка колонкою з Excel/CSV, через кому чи крапку з комою. Координати в тексті знаходяться як підрядки, усе навколо (назви міст, дужки) ігнорується.
3. Кнопка «Перевірити цілі» рахує відстань (формула гаверсину) від кожної цілі до кожної точки інтересу.
4. У таблицю результатів потрапляють **лише** цілі, що опинились у радіусі хоч однієї точки — сама їхня присутність у списку і є фактом влучання.

Рядок цілей, у якому взагалі не знайдено жодної координати, не зникає мовчки — про нього повідомляє текст під полем. А от текст-шум навколо координати, яку таки знайшли в тому ж рядку (назва міста, тире, дужки), просто ігнорується без попередження.

## Куди дивитись новачку

1. `core.js` → `convertOne()` — авто-визначення MGRS/WGS84 для одного рядка.
2. `core.js` → `extractCoordinateTokens()` / `parseFreeform()` — пошук координат у довільному тексті цілей.
3. `core.js` → `haversineKm()` — відстань між двома точками по земній кулі.
4. `core.js` → `findHits()` — зв'язує точки інтересу, цілі й радіус у фінальний список влучань.
5. `app.js` → `runCheck()` — викликає `core.js` і малює результат у DOM.

## Що навмисно не зроблено

Один спільний радіус для всіх точок інтересу (а не свій на кожну — хоча тепер і їх 4 варіанти), без збереження точок інтересу між сесіями. Можна додати пізніше, коли знадобиться.
